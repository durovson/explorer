# Запуск на Telegram Serverless

Проект запускается внутри Telegram как JavaScript-модули в V8. Python/aiogram,
VPS, Render и внешняя база не нужны. Локальный Node.js нужен для CLI, проверки
и генерации настроек; версия проекта указана в `package.json`.

Платформенный контракт проверен 11 октября 2026 года по
[официальной документации](https://core.telegram.org/bots/serverless) и
`@tgcloud/cli` 0.2.0. Справочник SDK поставляется в `docs/tgcloud-sdk.md`.

## 1. Установить зависимости и проверить проект

Из корня отдельного проекта:

```powershell
npm ci
```

`npm ci` использует `package-lock.json`. В runtime не передаются npm-пакеты:
деплоятся только `.js` внутри `tgcloud/`. Проверка компилирует каждый такой
файл через `node --check`, проверяет доступные SDK imports, относительные `.js`
ссылки и запрещенные Node API. Она также обнаруживает остатки старой структуры
Python/Render/Supabase. Успешная локальная проверка не подтверждает работу
облачной среды с реальными ключами.

## 2. Заполнить локальные настройки

```powershell
Copy-Item -LiteralPath config/operator.example.json -Destination config/operator.json
```

Заполнить в `config/operator.json`:

- `receiverAddress` — кошелек получения TON и USDT в основной сети TON;
- `toncenterApiKey` — ключ индексатора TON Center; `toncenterV3Url` — API v3;
- `fragment.jwt` — JWT выбранного провайдера отправки Stars/Premium;
- `botUsername`, `supportUrl`, `miniAppUrl`, `adminIds` — настройки оператора;
- `priceSource: "fragment"` — свежая база Fragment перед выбором валюты; `manual` — явно заданная оператором база;
- `stars` — базовая цена за звезду, наценка `markupRatio` (точная дробь numerator/denominator) либо `markupBps` и фиксированная дополнительная комиссия `providerFee` отдельно для TON и USDT; 100 basis points равны 1%. Ненулевая `markupBps` вместе с `markupRatio` запрещена;
- `premium` — итоговые цены за 3, 6 и 12 месяцев в каждой валюте.

Суммы задаются десятичными строками: TON допускает до 9 знаков после точки,
USDT — до 6. Пустой тариф означает, что тариф пока недоступен. Сетевая комиссия
кошелька оплачивается отдельно от суммы покупки. `scanLimit` и `scanMaxPages`
ограничивают объем одной проверки индексатора, `paymentTtlSeconds` — время счета.

`usdtMaster` закреплен за официальным USDT в сети TON:
`EQCxE6mUtQJKFnGfaROTKOt1lZbDiiX1kCixRv7Nw2Id_sDs`.
Его подтверждает [документация TON](https://docs.ton.org/applications/walletkit/android/data).
Другой master отклоняется, даже если у токена такое же название.

Сравнительные ставки Stars в шаблоне уже отмечены `pricingVerified: true`; метод расчета и ограничения приведены в `docs/REFERENCE-BOT.md`. Если меняете базу или надбавку, сначала сверить новые цены и комиссии.
Включать `salesEnabled: true` можно только с корректным адресом, обоими ключами
и положительным тарифом Stars в TON. Поля Premium пока пустые: заполните их перед продажей Premium.

```powershell
npm run configure
npm test
npm run check
```

`configure` валидирует JSON и создает `tgcloud/lib/operator-config.js` с
`export const operatorConfig = {...}`. Файл содержит реальные ключи и отправляется
в Telegram вместе с backend-модулями. `config/operator.json` и сгенерированный
модуль должны оставаться вне Git; не отправляйте их в переписку или публичный
архив. Скрипт не выводит значения ключей. В документированном SDK пока нет
runtime secret manager или `process.env`: этот проект не использует выдуманный
API для секретов. Доступ к Serverless-коду в BotFather и CLI токену также дает
доступ к настройкам оператора.

Без сгенерированного модуля либо с безопасной заглушкой `check` выводит предупреждение;
шаблон работает с выключенными продажами. При ошибке `configure` деплой необходимо
остановить, исправить локальный JSON и повторить обе команды. Скрипт не заменяет
последний корректный модуль при ошибке валидации.

## 3. Подключить своего бота

В `@BotFather` открыть своего бота → **Serverless** → включить функцию.
Затем открыть **CLI Access → Access token**.

```powershell
npx tgcloud login
npx tgcloud status
npx tgcloud diff
```

CLI токен имеет вид `app<ID>:<secret>` и отличается от обычного Bot API токена.
Передайте его только интерактивному `login`. CLI сохраняет машинные credentials
в исключенной из Git `.tgcloud/`; читать и изменять ее вручную не нужно.
В CI допустим `TGCLOUD_TOKEN` для авторизации CLI, это не runtime env бота.

Свой бот, CLI токен и платежные ключи в этом комплекте не предоставлены.
Login, deploy, миграция и реальные покупки при подготовке проекта не выполнялись.

## 4. Выложить код и применить схему

```powershell
npm run configure
npm run check
npx tgcloud push
npx tgcloud migrate --dry-run
npx tgcloud migrate
npx tgcloud webhook
```

`push` атомарно отправляет код, но не создает таблицы. `migrate` отдельно
показывает изменения схемы и применяет их после подтверждения. Проверяйте
предложение перед выполнением; не используйте `--yes` для непроверенных
изменений. `--safe` подходит только для уже рассмотренных безопасных добавлений.
Для нового проекта порядок — сначала код, затем таблицы, затем проверка бота.

Webhook управляет Telegram. При рассинхронизации:

```powershell
npx tgcloud webhook sync
```

Не устанавливайте внешний webhook вручную и не запускайте `getUpdates`.
Не используйте `--drop-pending` без решения о потере ожидающих updates.

`npx tgcloud run` выполняет локальные модули на реальной платформе, обращаясь
к настоящей базе и Bot API. Он не является изолированным локальным тестом:
используйте тестового бота/чат и проверяйте payload перед запуском.

## 5. Проверить покупки и обслуживание

Открыть `/start`, выбрать Stars/Premium, проверить получателя, цену, наценку,
комиссии и условия счета. Для тестов использовать отдельного бота, кошелек
оператора и минимальную сумму; результат оплаты должен подтверждаться поиском
транзакции в сети, а не утверждением клиента.

В режиме Fragment проверить в облаке исходящий GET к `fragment.com/stars/buy`, доступ к anonymous `Set-Cookie` и POST публичного `updateStarsPrices`. Это чтение цены без покупки или подключения кошелька. Локальная проверка этого протокола прошла на живом сайте, но доступ SDK из Telegram еще не проверен. Изменение cookie/nonce/HTML останавливает расчет без скрытого перехода на старый тариф. Для USDT база — USD-номинал Stars при явно указанном 1 USD = 1 USDT; надбавка включает расходы сервиса. `providerFee: "0"` не означает отсутствие расходов провайдера: оператор оплачивает их из надбавки.

В доступной документации нет scheduler/cron API. Бот проверяет оплаты при
нажатии кнопки проверки и других обработанных updates. Он не обещает
самостоятельно опрашивать сеть в фоне. При задержке индексатора повторить
проверку; успешный платеж нельзя выдавать за подтвержденный до валидации
транзакции. Mini App endpoints также не подходят для публичного callback
платежного провайдера: Telegram принимает их только с проверенными initData
пользователя собственного Mini App.

Перед очередным изменением проверить `npx tgcloud status` и `npx tgcloud diff`.
При конфликте ревизии сначала `npx tgcloud fetch` и согласование изменений;
`push --force` не нужен для обычной работы. Схему и данные меняют отдельно;
`pull` или возврат к предыдущему коду не откатывает базу.
